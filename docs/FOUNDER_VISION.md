# CATTIPU OS — Founder Vision
### (Permanent Project Constitution)

This document is the north star for every future sprint on CATTIPU OS. It exists so that no
sprint — however well-intentioned — accidentally turns CATTIPU into a Windows clone or a
generic AI dashboard. Every sprint brief should be read against this document first.

---

## The Mission

CATTIPU OS is an AI-native operating system for **building software** — not a replacement for
Windows, macOS, or Linux, and not an attempt to recreate a desktop operating system for its own
sake. The desktop metaphor (windows, a dock, a file explorer, a command palette) is the
*interface*, not the *point*. The point is that every project a person opens is a living
workspace: its architecture, its database, its APIs, its roadmap, its code, its deployment, and
its own memory of itself all live inside one coherent surface, instead of being scattered across
a chat window, a whiteboard tool, an ERD tool, an API doc tool, and a project tracker.

## Core Philosophy

CATTIPU is **project-first, not chat-first**. A chat transcript is disposable; a project is not.
Every project CATTIPU creates is a living workspace — it persists, it can be reopened exactly as
it was left, and every part of it (the architecture graph, the schema, the API catalog, the
roadmap) stays connected to every other part instead of existing as one-off, disconnected
generations.

## The CATTIPU Workflow

CATTIPU's pipeline has five stages, and a project moves through them in order:

1. **Idea** — the founder describes what they want to build, in their own words.
2. **Architect** — CATTIPU turns the idea into a real, editable system architecture: services,
   data stores, APIs, events, and a roadmap.
3. **Canvas** — the architecture becomes a visual, interactive product surface.
4. **Forge** — the architecture becomes real, running code.
5. **Launch** — the project ships.

After Launch, the project doesn't disappear — it becomes a **Living Project**: something that
can be reopened, extended, and re-architected as it grows.

## The User

CATTIPU is built for student developers, indie founders, hackathon teams, and solo builders —
people who need to move from an idea to a real system quickly, without a team of specialists,
and without losing the rigor that a real system needs.

## What We Are NOT Building

To keep every sprint honest, here is the explicit list of things CATTIPU OS is not:

- ❌ A Windows replacement
- ❌ A Linux kernel
- ❌ A Windows clone
- ❌ A generic AI chat app
- ❌ Another Cursor skin
- ❌ Another Notion clone

If a sprint's output starts to resemble any of the above, it has drifted from the mission.

## The Visual Identity (Permanently Locked)

CATTIPU's visual identity takes inspiration from Mac OS 8, BeOS, Haiku, and MenuetOS — but it
must never imitate any of them directly. The personality is **playful, tactile, and inventive**.

The CATTIPU thumb logo has its own rules and must never be recreated, redrawn, distorted, or
substituted — it is the one fixed visual anchor of the product.

Motion follows one philosophy: **120–180ms, mechanical, not magical.** Every animation should
feel like a physical, engineered mechanism clicking into place — never like a special effect.

## The Standout Feature: Build Playback

Build Playback is CATTIPU's signature moment — the sequence where a generated architecture
visibly assembles itself on screen, piece by piece. It is the single feature most likely to make
someone say "I've never seen software do that before," and every sprint that touches it should
protect and sharpen that feeling rather than dilute it.

## Product Roadmap

- **v0.2.5** — Identity locked (visual language finalized)
- **v0.3** — Architect made production-worthy
- **v0.4** — Forge
- **v0.5** — Launch
- **v1.0** — CATTIPU Desktop

## Engineering Principles

- Never rebuild a working system without a real reason to.
- Extend existing stores before creating new ones.
- Reuse visual primitives — don't invent new ones per feature.
- Pixel-perfect consistency beats shipping one more feature.
- Every new app must justify why it belongs in an operating system, not just why it'd be useful
  on its own.

## The Ultimate Vision

CATTIPU OS exists to make the distance between "I have an idea" and "I have a real, working
system" as short as it can honestly be — without pretending that distance is zero. It is not
trying to be an operating system that happens to have AI in it. It is trying to be the first
operating system built *for* building software with AI, from the ground up.
