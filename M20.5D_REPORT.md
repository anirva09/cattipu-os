## Audit Findings

Read before writing anything: `PROJECT_CONSTITUTION.md`, `CLAUDE.md`,
`AGENTS.md`, `docs/architecture/BOUNDARY_AUDIT.md`, the diagnostics contracts
and service (`lib/contracts/diagnostics/{types,service}.ts`,
`lib/services/diagnostics/{diagnosticsService,healthRegistry,staticChecks}.ts`),
and — because BOUNDARY_AUDIT.md §2.3 flags window registration as the
sprint's stated risk — `components/WindowManager/*`,
`components/InteractiveDesktop/InteractiveDesktop.tsx`, `components/Window/*`,
`components/Sidebar/Sidebar.tsx`, `design-system/*`, and
`store/useSettingsStore.ts`.

Confirmed from BOUNDARY_AUDIT.md and by re-reading the code directly:

- `DiagnosticsService.getSnapshot()` already returns one `ServiceHealth` per
  `DiagnosticCategory` (12 total) plus cross-cutting `checks[]` — exactly the
  shape a panel needs, with no gaps to fill.
- `CATTIPU_WINDOW_IDS` (`components/WindowManager/windowManager.reducer.ts`)
  is a fixed 5-element tuple, and `parseWindowManagerState` requires every
  listed id to be present in a saved `sessionStorage` snapshot or the whole
  session is discarded (§2.3, §10 of the sprint brief). Adding a 6th
  `"diagnostics"` window id would invalidate every session saved before this
  sprint on its first load afterward.
- The sprint brief itself offers a third option ("expose Diagnostics through
  an existing Settings/System surface instead") precisely to avoid that
  migration when it is not required.
- `SettingsApp.tsx` already opens through the canonical `settings` window id
  and is already a tab strip of self-contained sections (Appearance, Dock,
  Cursor, Sound, Notifications, About) — adding a seventh section changes no
  window id, no session shape, and no app registry.
- No PixelForge asset exists for a status lamp/indicator (checked
  `components/PixelIcon/shellIcons.ts`, the frozen Sheet 01 registry — 22
  marks, none of them a status glyph). Per the missing-asset rule
  (Constitution §26 / DESIGN_CONSTITUTION), the correct response is to report
  the gap and use the bracket-glyph vocabulary the sprint brief itself
  specifies (`[●] READY`, `[!] DEGRADED`, ...), not to substitute a generic
  icon library or manufacture a new PixelForge asset without authorization.

## Canonical Ownership

- **Diagnostics aggregation** — `lib/services/diagnostics/diagnosticsService.ts`
  (M20.5C). Unchanged. The new UI calls `diagnosticsService.getSnapshot()`
  and nothing else; it computes no status and reads no store.
- **Window management** — `components/WindowManager/*`. Unchanged. No new
  window id was registered, so the session-invalidation risk in
  BOUNDARY_AUDIT.md §2.3 does not apply to this sprint at all.
- **Settings surface** — `components/Window/SettingsApp.tsx`. Extended with
  one more section, the same way Notifications was added in M12.
- **PixelForge** — `components/PixelIcon/*`. Reused (`ShellIcon` /
  `terminal`, CAT-SYS-001) for the new nav entry rather than adding another
  `lucide-react` import or a fourth icon family.

## Changes

- **`components/Diagnostics/DeveloperDiagnostics.tsx`** (new) — the panel.
  Loads a snapshot on mount, exposes a manual REFRESH / RECHECK button (no
  polling timer), and renders SYSTEM SUMMARY, SERVICES and KNOWN ISSUES /
  ARCHITECTURE DRIFT from the snapshot it received. Owns three states —
  loading, error, ready — rendered as period-correct text
  (`LOADING DIAGNOSTICS...`, `DIAGNOSTICS UNAVAILABLE — <message>`,
  `LAST OBSERVATION: <time>`), no spinner.
- **`components/Diagnostics/ServiceHealthRow.tsx`** (new) — one SERVICES row
  (name, status, version/planned milestone, its own checks) and the shared
  `StatusBadge` the checks list also uses, so there is exactly one place
  that draws the status vocabulary.
- **`components/Diagnostics/DiagnosticsChecks.tsx`** (new) — renders
  `snapshot.checks` (the cross-cutting architecture-drift findings) directly;
  no local copy of the boundary-audit findings.
- **`components/Diagnostics/diagnosticsPresentation.ts`** (new) — pure
  helpers with no React/store/service dependency: the bracket-glyph→label
  map, service-status counting for the summary row, and safe
  error/timestamp formatting. Kept separate so the mapping is unit-testable
  without a DOM.
- **`components/Diagnostics/Diagnostics.css`** (new) — panel styling built
  entirely from `design-system/bevel.css` classes and `cattipuTokens`
  colors (Status Green / Welcome Gold / Projects Red for
  ready/degraded/offline; neutral outer-frame ink for not-implemented/
  unknown). No new hex values, no rounded cards, no gradients/blur.
- **`components/Window/SettingsApp.tsx`** (modified) — added a "Diagnostics"
  entry to the existing `SECTIONS` nav (between Notifications and About) and
  the corresponding render branch. The nav icon is a 3-line local wrapper
  (`DiagnosticsNavIcon`) around the existing PixelForge `ShellIcon` mark
  `terminal`, fitted to the same `{ className, strokeWidth }` shape every
  other section's `lucide-react` icon already uses — no new `lucide-react`
  import, no new icon family.
- **`tests/diagnostics-ui.test.ts`** (new) — 14 assertions against the
  presentation helpers and the real `diagnosticsService` snapshot; see
  Tests below.
- **`package.json`** (modified) — added `tests/diagnostics-ui.test.ts` to the
  `test` script's chain, in the same `tsx ... && tsx ...` style as every
  existing suite.

## Existing Systems Reused

- `design-system/bevel.css` (`cattipu-bevel--raised`, `cattipu-bevel--inset`,

  `design-system/tokens.ts` (`cattipuCssVariables`, `cattipuTokens.colors`) —
  the same primitives `Window.tsx`, `RightWidgetStack.tsx` and
  `BottomStatusBar.tsx` already use.
- `components/PixelIcon` (`ShellIcon`, `terminal` mark) for the new Settings
  nav icon — PixelForge, not `components/Icons` (legacy) or a new
  `lucide-react` import.
- `components/Window/SettingsApp.tsx`'s existing section-tab pattern — no new
  window, no new app id, no new sidebar item.
- The existing `Window` / `ManagedWindow` chrome around Settings — the panel
  content only fills that window's body; it does not draw its own window
  frame.

## Architecture Impact

- **Windows** — no new window id was added to `CATTIPU_WINDOW_IDS`, so
  `parseWindowManagerState`'s "every listed id must be present" check is
  untouched and no existing saved session is invalidated by this sprint.
  `components/WindowManager/*` was read for the audit above and not modified.
- **App registries** — no new entry was added to `AppId` (legacy store),
  `CATTIPU_SIDEBAR_ITEMS`, or any other registry; Diagnostics is reached
  exclusively through the existing `settings` window and its section tabs,
  so no fourth registry was created.
- **Diagnostics ownership** — the service remains the single diagnostics
  aggregation owner. Verified structurally: `tests/diagnostics-ui.test.ts`
  greps the three new component files for a `store/` import or a
  `.getState()` call and fails the suite if either appears.
- **PixelForge** — no new icon family, no `lucide-react` growth; the one new
  nav icon reuses a frozen Sheet 01 mark.

## Visual Preservation

Golden Master surfaces deliberately not touched: `TopBar`, `Sidebar`,
`BottomStatusBar`, `RightWidgetStack`, `ManagedWindow`, `Window` chrome,
boot sequence, wallpaper, every other Settings section
(Appearance/Dock/Cursor/Sound/Notifications/About). The new panel uses only
existing bevel/token primitives — no glassmorphism, blur, rounded modern
cards, pill badges, gradients, or a generic icon library. Status is never
color-only: every status renders as a bracket glyph *and* an uppercase text
label (`[●] READY`, `[!] DEGRADED`, `[X] OFFLINE`, `[-] NOT IMPLEMENTED`,
`[?] UNKNOWN`) — verified in `tests/diagnostics-ui.test.ts`.

## Data / Migration Impact

None. No persisted schema changed. `DiagnosticsSnapshot` is fetched fresh on
every load/refresh and held only in local component state — nothing new is
written to `localStorage` or `sessionStorage`.
